# 중지·종료 후 전환 집계 정책 결정

> 최신 상태: 2026-11-14 운영 반영·런타임 확인 완료([PR #39](https://github.com/Pseudo-Lab/experiment-platform-pseudolab/pull/39)). 아래의 미커밋·운영 미반영 표현은 해당 단계 당시 기록이다. 실제 Google 계정 선택·동의 및 지정 이메일 초대 수락은 아직 확인하지 않았다. 상세 근거는 [운영 반영 기록](handoffs/2026-11-13-experiment-status-history.md#운영-반영-완료--2026-11-14)을 따른다.

## 결정 범위와 현재 상태

사용자는 ‘다른 실험 플랫폼들이 어떻게 하는지 Gemini와 협업해서 리서치하고 결정’하도록 요청했다. 아래는 Codex가 공식 문서와 Gemini Argon High의 독립 조사를 대조해 채택한 제품 정책이다. 정책 결정과 구현·운영 반영을 구분한다.

사용자는 두 방향을 확인하고 동의한 뒤 기본 집계 경계의 로컬 구현·검증을 위임했다. 현재 로컬 코드는 신규 SDK A/B 실험의 활성 구간 판정에 더해 명시적 전환 창 W·수신 유예 상한 L·불변 집계 확정과 KO/EN 화면까지 구현했다. 기본은 활성 구간 행동만 집계하고, 시작 전 일회성 노출 효과와 W를 명시한 실험만 후속 행동을 관찰한다. 아래 단계별 기록과 최신 구현 절을 구분한다. 기존 운영 실험과 결과를 이 문서만으로 소급 변경하지 않는다.

## 채택한 정책

1. **기본 방식은 활성 실험 기간 기준이다.** 적격 노출 이후, 실행 중인 구간에 발생한 행동을 집계한다. 일시중지·종료 후 새로 발생한 행동은 기본 방식에서 제외한다. 활성 구간에 발생했지만 늦게 도착한 전송은 별도의 유예 조건으로 판정한다.
2. **종료 후 관찰은 실험 시작 전에 선언한 전환 인정 기간이 있는 경우에만 허용한다.** 일회성 화면·메시지 등 노출 이후 효과가 남는 실험에서 사용한다. W의 기준은 사용자의 첫 적격 노출이며 양쪽 군에 동일하게 적용한다. 매 노출이나 재개 때마다 W를 다시 시작하지 않는다. ‘종료 후 모든 사용자에게 일괄 7일 추가’ 방식은 채택하지 않는다.
3. **지속적인 처치가 필요한 실험은 제공 중단 시각을 행동 경계로 삼는다.** 추천 알고리즘처럼 기능을 계속 제공해야 효과를 측정할 수 있는 실험에서, 제공을 중단한 뒤의 행동을 일회성 노출 효과와 같은 방식으로 합산하지 않는다. 기존 사용자에게 계속 같은 기능을 제공하는 enrollment freeze는 현재 구현 범위에 추가하지 않는다.
4. **사용자 전환 시간 W와 전송 지연 L을 분리한다.** 전환 기간 안에서 실제 발생한 행동이 늦게 도착한 경우만 수신 유예로 다룬다. L 때문에 행동 인정 기간 자체가 늘어나지는 않는다. 시각 생략은 서버 수신 시각을 사용하되 잘못된 클라이언트 시각을 정상 시각으로 바꿔 통과시키지 않는다.
5. **명시적 전환 창이 남아 있으면 ‘관찰 중’, 관찰·수신 유예가 끝난 뒤 ‘확정’으로 구분한다.** 확정 결과는 지표·변형·정책 버전에 묶인 재현 가능한 기록으로 남긴다. 단순한 현재 시각 비교나 SQL WHERE 조건만으로 영구 동결을 보장한다고 하지 않는다.
6. **과거 실험과 원본 데이터는 보존한다.** 새 정책은 선언된 새 버전에 적용한다. 이력 없는 기간을 추정하거나 기존 숫자를 조용히 재분류하지 않는다. 재분석이 필요하면 별도 결과로 구분한다.

## 선택 이유와 한계

앞선 ‘종료 후 행동을 일정 기간 일괄 인정하자’는 권장안을 보완했다. 플랫폼 사례는 보편적인 기간보다 실험·지표에 선언한 창과 종료 동작을 구분하는 방향을 뒷받침한다. 기본 화면은 단순하게 유지하고 후속 전환이 필요한 실험에서 명시적 관찰 기간을 제공하는 방식을 선택했다.

기본 방식에서는 종료 직전에 유입된 사람이 행동할 시간이 짧다는 관찰 중도 절단 문제가 남는다. 동일한 관찰 기간이 필요한 지표라면 전환 창을 정하고 마지막 참여자의 관찰이 끝날 때까지 기다려야 한다. 일시중지 시간도 경과 시간에 포함하며, 중단으로 실험 내용이 바뀌었다면 재개로 조용히 합산하지 않는다.

W는 실제 실험 설계 때 정하는 측정 조건이다. 지금 진수님에게 플랫폼 정책이나 숫자 결정을 요청하며 QA를 기다릴 사항이 아니다. 이번 공식 문서 조사에서 L의 업계 공통값을 확인하지는 않았다. 후속 구현에서는 전송 계약의 초기 기술 선택으로 L=24시간을 고정했다. 이는 모든 실험의 W를 24시간으로 설정한다는 의미가 아니다.

## 후속 구현: 기본 활성 구간 — 로컬 검증 완료

- migration 043은 새 SDK A/B 실험에만 `active_period_v1`을 생성 시 원자적으로 부여한다. 기존 실험에는 부여하지 않고 버전 UPDATE를 막는다. 정상 앱 경로의 버전 고정이며 DB 관리자에 대한 변조 방지는 아니다.
- 최초 이벤트 INSERT 한 문장 안에서 041의 상태 이력과 실제 상태를 읽는다. UTC로 정규화한 발생 시각이 실행 구간 `[시작, 중지)` 안인지 판정해 `sdk_active_period_eligible` 0/1을 저장한다. 기존 서버 수신 상태 기반 노출 guard도 유지한다. 사용자 marker는 제거하고 재전송은 최초 판정을 유지한다.
- 실행 중 발생해 중지 뒤 늦게 도착한 행동은 적격 노출과 연관되면 포함한다. 중지 중 발생해 재개 후 전송된 행동은 제외한다. 정책 실험은 노출과 행동 양쪽에 수집기 판정 1이 있어야 하며, 판정이 없는 구형 수집기 이벤트를 추정해서 포함하지 않는다. 정책 없는 과거 실험의 임의 동명 속성은 새 판정으로 해석하지 않는다.
- 시각 생략은 서버 수신 시각을 사용하고 쓰기 시점에도 running이어야 한다. 제공된 시각이 수신 시각보다 미래면 원본은 보존하되 집계에서 제외한다. 임의 시계 오차 허용 폭이나 과거 시각 대체는 추가하지 않았다. 따라서 클라이언트 시계가 빠르면 실제 행동도 제외될 수 있다. 유효한 형식의 과거 클라이언트 시각이 진실임을 증명하는 기능은 아니다.
- 041의 DB 시각은 밀리초 정밀도다. 고정 UTC 마이크로초 문자열로 비교해 SQLite의 추가 반올림을 피하되 물리적 DB 시계가 마이크로초 정밀도라는 뜻은 아니다. 같은 DB 시각의 상태는 ID 순서로 판단하고, 이미 저장된 이벤트 판정은 뒤의 같은 시각 전환으로 소급 변경하지 않는다. 이력 누락·형식 이상·시간 역전·상태 불일치·연결 단절은 새 이벤트의 집계 자격을 부여하지 않는다.
- 새 회귀 **30사례**, 관련 **65개**, 최종 단독 전체 **615개**, 기존 API 검증·Google 프로필/초대 변경까지 합친 격리 통합본 **680개**를 통과했다. 기존 의존성 경고 6개가 있다. 프런트엔드/API 응답·SDK 패키지를 변경하지 않아 UI 빌드·브라우저 검사는 반복하지 않았다.
- Gemini/agy Argon High와 독립 설계를 대조했고, 생략 시각의 쓰기 시점 중지 경쟁 및 이력 이상 점검에 활용했다. 직접 코드·SQL·회귀 테스트로 검증했으며 문자열 정규화 방식과 추가 정책 시각 컬럼 제안은 그대로 채택하지 않았다. 설계 파일은 회수했지만 Gemini 사용량 한도로 최종 코드 리뷰는 실행되지 못했다. 초기 과도한 경로 탐색과 조율 비용이 있었고 모델을 임의 변경하지 않았다.
- 근거: `/home/ubuntu/.codex/reviews/iterglow-active-period-20261114/`의 `design-review.md`, `final-focused-tests.log`, `backend-final-tests.log`, `combined-tests.log`. 상세 운영 조건은 기존 상태 이력 인계 문서의 최신 절을 따른다. 변경은 미커밋이며 운영 미반영이다.

## 후속 구현: 전환 창·수신 유예·불변 확정 — 최신 로컬 상태

### 적용 대상과 시간 계약

- migration 044 이후 생성한 SDK A/B 실험만 `bounded_v1` 계약에 등록한다. 기존 무정책 실험 및 043만 적용된 실험을 소급 전환하지 않는다. 첫 실행과 같은 SQL 변경에서 지표·변형·정책·W/L을 잠근다. flag가 반환할 수 있는 기본 control/treatment와 활성 규칙 변형을 모두 실행 계약에 기록한다.
- W는 기본값 없이 선택한다. API는 정수 1초~30일, UI는 시간 단위를 입력받는다. 명시적 일회성 노출 효과 확인이 필요하다. 첫 적격 사용자 노출부터 `[최초 노출, 최초 노출+W)`이며 반복 노출·일시중지·재개로 새로 시작하지 않는다. W가 없으면 이전의 활성 구간 기준을 따른다.
- 수신 유예 L=86,400초는 제품 초기 기술 선택이며 공식 사례에서 확인한 보편적 기본값이 아니다. 각 이벤트는 `발생 <= 수신 <= 발생+L`을 만족해야 한다. 미래 시각을 현재로 고쳐 통과시키지 않는다. 시각 생략은 서버 수신 시각을 사용한다. 원본 202 보존과 첫 event_id의 멱등성은 유지한다.
- 실제 종료 이력의 시각 E를 기준으로 `E+(W 또는 0)+L`까지 관찰한다. 정확히 기한과 같은 시각에는 아직 관찰 중이며 이후 최초의 권한 있는 조회에서 확정한다. 일시중지는 확정 기한 없이 관찰 중이다. 한 번도 시작하지 않은 초안·보관 초안은 상태/기한 메타데이터가 null이고 확정 기록을 만들지 않는다. 예약 종료일을 실제 종료 이력 대신 사용하지 않는다.

### 확정과 화면

- 하나의 부모 INSERT와 그 AFTER trigger 안에서 계약 및 집계 후보 입력을 이벤트별 행으로 복사하고 봉인한다. 전체 입력을 하나의 JSON 값으로 묶지 않고, 귀속에 필요한 8개 SDK 속성만 복사한다. 봉인한 입력에서 계산한 결과 JSON을 메타데이터 행에 조건부로 한 번만 저장한다. 늦게 실행된 이벤트 INSERT, 중복 확정 요청, 결과 저장 전 중단·재시도에도 이긴 입력과 결과를 사용한다. 이후 원본 추가·삭제나 지표 수정으로 확정 결과를 다시 계산하지 않는다. bounded 결과만 버전으로 묶인 PCG64 seed 0을 사용한다.
- 이력 단절·시간 역전·설정 불일치·D1 오류는 503으로 처리하고 빈 결과를 확정하지 않는다. 시작 전 지표·W·일회성 여부를 편집/초기화할 수 있고 첫 실행 후 잠근다. 이름·설명 수정은 가능하다. 기존 SDK 연결 flag의 교체 버튼은 노출하지 않으며 flag의 서비스 제공 설정 자체를 실험 중지와 혼동하지 않는다.
- KO/EN으로 선택형 전환 기간, 첫 시작 시 설정 고정 안내와 수집 중/관찰 중/확정·예정 시각을 표시한다. 1초도 0시간으로 잘못 표시하지 않는다. 일반 멤버에게는 analytics의 이벤트 합계와 상태만 반환한다. 기존 `/result`의 설치 관리자 전용 403 경계와 조회자 수정 불가를 유지한다.

### 운영 전 조건과 제한

- 041/043/044 스키마를 새 backend보다 먼저, trigger 전체 문장을 실행할 수 있는 승인된 Ops 경로에서 적용한다. 프로필 기능을 함께 반영하면 042도 필요하다. 044에는 ALTER가 있어 적용 기록을 확인하는 1회 migration이며 무조건 재실행하지 않는다. 기존 run_migration.sh의 세미콜론 분할 경로는 사용하지 않는다.
- migration과 새 수집기 사이에는 신규 정책 실험 생성/수집을 진행하지 않는다. 구형 앱은 새 판정·계약·확정을 모르므로 롤백 시 관련 실험의 수집/결과 제공을 멈추고 검증한다. 새 테이블·원본·이력을 지우거나 과거 실험을 보정하지 않는다.
- 초기 단일 JSON 입력 방식은 공식 2,000,000바이트 제한을 적용한 SQLite에서 6천 이벤트 조회 실패를 재현해 교체했다. 이벤트별 입력 행과 별도 메타데이터/결과로 보존하며, 조회도 메타데이터 헤더 1행과 개별 이벤트 행을 한 SQL 문장에서 반환한다. provider의 쿼리 전체 응답 크기·시간 한도는 여전히 적용되며 초과 시 503으로 실패하고 잘라 저장하지 않는다. 로컬 workerd SQL 호환성과 공식 한도를 적용한 회귀는 확인했지만 원격 D1 용량·부하·배포 경로 검증은 하지 않았다. 확정 입력에는 사용자/이벤트 식별 정보가 복사되므로 개인정보 보존·삭제·탈퇴 안내의 검토 대상에 포함해야 한다. 실험 삭제의 FK 정리는 유지하지만 개별 사용자 탈퇴 처리가 완성됐다는 의미는 아니다.
- 상세 테스트 결과와 운영 인계는 [상태 이력·집계 인계](handoffs/2026-11-13-experiment-status-history.md)의 최신 절에 기록한다. 현재 변경은 로컬 미커밋이며 GitHub·운영·Hub는 변경하지 않았다.


## D1 저장 보완의 검증 근거

- [공식 D1 제한](https://developers.cloudflare.com/d1/platform/limits/)은 문자열/BLOB/행 2,000,000바이트, SQL 100,000바이트, 바인딩 100개, 함수 인자 32개다. 현재 계약 JSON 함수는 30개 인자를 쓰므로 향후 필드 추가 시 이 제한을 다시 확인해야 한다.
- Wrangler 4.162.0 / workerd 1.20261113.1의 로컬 D1 binding에서 complete statement와 batch를 검사했다. 로컬 런타임은 2.1MB 문자열도 허용했으므로 그 성공을 원격 용량 증거로 삼지 않는다. 별도의 SQLite LIMIT_LENGTH=2,000,000에서 6천 건 회귀를 검증했다. 단독 백엔드 659개, 프로필/API 검증을 합친 통합본 724개가 통과했다.
- 원자적 migration batch 중간에 의도적 오류를 넣어 044의 앞선 ALTER와 새 테이블 생성까지 전부 롤백됨을 확인했다. 재적용은 duplicate column 오류이므로 실제 적용 이력/현재 스키마를 먼저 확인해야 한다. 기존 generic runner는 변경하지 않았다.
- 입력은 (실험, 원본 이벤트 ID)로 구분한다. INSERT가 후보 복사 후 input_sealed=1로 봉인하며, 봉인 뒤 추가/수정/삭제를 거부한다. 원본 이벤트와 FK로 연결하지 않아 원본 삭제에 영향받지 않고, 실험 삭제 시 메타데이터와 함께 cascade한다. 저장 방식 보완이며 전환·귀속 버전은 바꾸지 않는다. 향후 귀속 의미를 바꿀 때에는 frozen 입력의 버전별 해석을 유지해야 한다.
