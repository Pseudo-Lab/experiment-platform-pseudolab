# 12기 일회성 회고 신규 제출 종료

사용자는 LVUP 총괄 대화에서 12기 회고 종료 작업을 지시했으며 기존 회고 데이터는 반드시 남기도록 명시했다. 이 변경은 `s12-mid-reflection`의 신규 제출만 종료한다.

## 동작과 보존

- 유효한 `POST /api/v1/reflections/` 요청의 experiment_id가 `s12-mid-reflection`이면 DB 접근 전에 HTTP 410을 반환한다. 기존 클라이언트나 직접 API 호출도 새 회고를 저장하지 못한다.
- 다른 실험의 제출·완료 이벤트 기록은 유지한다. 기존 회고 check와 관리자 summary도 유지한다.
- 마이그레이션, 삭제, 익명화, 기존 답변 수정, 로그 정리, 데이터 export를 하지 않는다.
- LVUP 변경은 프로젝트 홈의 전용 배너·decide 호출을 제거하고 옛 회고 링크를 종료 안내로 교체한다. 공통 실험 기반은 유지한다.

## 검증

`backend`에서 `python -m pytest -q`: 332개 통과. 신규 3개 검사는 종료 요청의 DB 접근 금지, 기존 답변·로그 전체 행 보존과 조회 유지, 다른 실험 제출·완료 이벤트 유지를 확인한다. 실제 운영 DB를 조회하거나 변경한 검사는 아니다.

## 운영 인계와 남은 확인

- 로컬 구현·검증 완료 상태이며 GitHub main·운영 반영 완료를 의미하지 않는다. main 반영은 기존 CI/GitOps 자동 배포를 시작하므로 승인된 경로를 따른다.
- 운영 실험·placement config 조회는 401로 실패했다. 현재 상태·종료일·enabled는 미확인이다. 승인된 관리 경로에서 이 실험만 종료 상태로, 해당 placement만 비활성으로 정리하고 기존 행·로그는 보존한다. DELETE API를 사용하지 않는다.
- 코드·migration·workflow 검색에서는 회고·이벤트 자동삭제를 찾지 못했지만 운영 DB·별도 스케줄러 정책은 미확인이다. 보존을 보장했다고 보고하지 않는다.
- 과거 폼에는 목적 달성 후 파기한다는 안내가 있었다. 최신 사용자 지시로 이 작업에서 모든 기존 데이터를 보존하며, 과거 동의를 소급 변경하지 않는다. 고지와 보존 기준의 정합성 확인은 별도 후속 사항이고 삭제 승인이 아니다.
