### 화면 배치와 검증 순서

1. 전체 지도와 현재 구현/개선 제안 표기를 배치한다. Button·Input/Field·Card·Navigation item·Table row는 기존 코드와 맞는 최소 공통 컴포넌트로 만들고 텍스트 속성을 노출한다. 새 범용 디자인 시스템 구축으로 확장하지 않는다.
2. 프로젝트→실험 목록→생성→설계→수집→결과→결정의 연속 과업을 먼저 검토한다. 다음으로 플래그·Placement·SDK, 소개/로그인을 같은 파일에 정리한다.
3. 로딩·조회 오류·최초 빈 데이터·필터 결과 없음·성공·저장 실패·권한 없음·파괴적 작업 확인을 상태 보드에서 구분한다. 조회 실패를 ‘없음’으로 바꾸지 않고, 저장 실패 시 입력 보존과 재시도를 보여준다.
4. 데스크톱 KO와 대표 모바일 EN으로 시작하되, 전 화면 KO/EN·light/dark·모바일 검증은 별도 완료 항목으로 남긴다. 모바일 표는 핵심 행 정보와 상세 진입을 보존하고, 긴 폼·사이드 메뉴·모달의 접근성을 확인한다.
5. 텍스트/인스턴스/변수 바인딩과 이미지 채움 여부를 읽고, 전체 화면 스크린샷에서 잘림·겹침·대비·글꼴을 검증한다. 정적 시안과 실제 작동하는 프로토타입의 완료 범위를 구분한다.

이번 프로젝트에 새 Figma 대상과 검토 범위를 기록했다. 앱 코드 수정·커밋·푸시·배포는 하지 않았으며 기존 미커밋 변경은 보존했다.
