# 프로젝트 접근·초대·자격증명

프로젝트는 서비스별 실험·flag·SDK 키와 구성원 접근을 관리하는 단위입니다. 설치 운영자는 [인증 설정](setup_guide.md#5-google-로그인과-운영-설정)을 준비하고, 연동 서비스는 자신의 프로젝트를 사용합니다.

## 사용자 역할

| 작업 | Viewer | Editor | Owner | 설치 관리자 |
| --- | --- | --- | --- | --- |
| 접근 가능한 프로젝트·실험·flag·구성원용 집계 조회 | 가능 | 가능 | 가능 | 가능 |
| 프로젝트 내 A/B 실험·flag 변경 | 불가 | 가능 | 가능 | 가능 |
| 공개 SDK 키 조회 | 불가 | 가능 | 가능 | 가능 |
| 구성원·초대 관리 | 불가 | 불가 | 가능 | 가능 |
| 프로젝트 설정·삭제·서버 credential 관리 | 불가 | 불가 | 가능 | 가능 |
| 설치 전체 분석·세그먼트·placement·`/result` 등 전역 기능 | 불가 | 불가 | 불가 | 가능 |

위 표는 현재 [권한 allowlist](../../backend/app/core/authorization.py) 기준입니다. 일반 계정의 실험 변경은 프로젝트가 연결된 A/B flag 실험 범위이며, owner 역할만으로 설치 전체 기능을 사용할 수 없습니다. 권한 없는 리소스는 403 또는 존재 노출을 줄이기 위한 404로 거부될 수 있습니다.

## 초대와 계정 식별

프로젝트 owner 또는 설치 관리자가 viewer/editor 초대를 생성합니다. 링크 초대와 이메일 지정 초대를 지원하며, 현재 앱은 메일을 발송하지 않습니다.

- 링크 초대: 원본 token을 받은 사람이 수락 가능한 방식. 링크 전달 대상의 관리 필요.
- 이메일 지정 초대: 해당 Google 이메일의 소유권이 확인된 계정에 연결. 일치하는 계정에서 대기 초대 목록 확인 및 명시적 수락·거절 가능.
- 초대 유효기간: 생성 후 7일. 만료·폐기·거절 상태는 수락 대상에서 제외.
- 원본 token은 생성 시 반환되며 DB에는 SHA-256만 저장. 목록 응답에서 token 재노출 없음.
- 하나의 계정에 수락된 초대의 다른 계정 재사용 거부. 멤버 제거·역할 변경은 기존 권한 경계 적용.

초대 링크는 권한을 부여하는 수단이므로 공개 이슈나 로그에 게시하지 않습니다. Google 프로필 이메일의 표시와 초대 수락에 필요한 이메일 소유권 검증은 구분됩니다.

## 세 가지 인증 수단

| 수단 | 사용처 | 취급 |
| --- | --- | --- |
| 사용자 세션 쿠키 | 프로젝트·실험 관리 API | 로그인 계정과 역할 범위 적용 |
| 공개 SDK 키 (`pk_sdk_...`) | 서비스의 SDK 평가·수집 | 브라우저 사용 가능. 관리자·서버 권한 없음 |
| 서버 credential (`sk_live_...`) | `/access/decide` 등 서버 요청 | 브라우저 금지. 서버 secret 저장소에 보관 |

프로젝트 일반 응답과 키 조회 경로는 구분됩니다. 인증된 `GET /api/v1/projects/{project_id}/api-key`는 공개 SDK 키 조회용이며 `Cache-Control: no-store`를 사용합니다.

## 서버 credential 생성·교체·폐기

- `POST /api/v1/projects/{project_id}/server-key`: 새 credential 생성·교체. 기존 활성 credential을 대체하므로 사용하는 서버와 전환 계획 확인 후 실행.
- `DELETE /api/v1/projects/{project_id}/server-key`: 활성 credential 폐기.
- DB에는 hash와 폐기 이력만 보관. 발급된 원본은 안전하게 보관하며 조회 목록에서 복구하는 방식으로 사용하지 않음.
- 공개 SDK 키로 서버 Bearer 요청 인증 불가. 누락·폐기·저장소 장애 시 공개 키로 fallback 금지.
- 응답 유실·409 충돌 시 무조건 재시도 금지. 실제 상태와 소비처를 확인한 뒤 다음 작업 결정.

공개 SDK 키 교체는 현재 [운영자용 서비스 함수](../../backend/app/services/project.py)의 별도 경로입니다. 일반 사용자용 키 교체 HTTP API가 있다고 가정하지 않습니다. 교체 전 대상과 소비처를 확인하고 키를 로그에 출력하지 않습니다.

## 삭제와 보존

프로젝트 삭제는 연결된 실험·flag와 서버 credential 이력을 확인합니다. 활성 또는 폐기 credential 행이 참조하는 프로젝트는 409로 삭제가 거부됩니다. 삭제를 위해 과거 credential·이벤트를 임의 정리하지 않습니다. 저장소 실패를 삭제 성공으로 해석하지 않습니다.

데이터 수집·직접 DB 접근·export는 [데이터 접근 가이드](data_access.md), 서버 정책 판정은 [서버 접근 판정 가이드](access-decision.md)를 참고합니다.
